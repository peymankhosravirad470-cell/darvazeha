# هفتاد و هفت سرزمین

بازی تعاملی فارسی (RTL) با تم سفر میان سرزمین‌ها. نسخهٔ فعلی، **نسخهٔ ساختاری v1** است:
اسکلت کامل تجربه با ۱۳ دروازهٔ اول و صحنهٔ اکتشافِ نمونه برای دروازهٔ نخست.

> یادداشت نام‌گذاری: پوشه و مخزن به‌دلایل تاریخی `darvazeha` نام دارد؛
> تغییر نام مخزن فقط با تصمیم مالک انجام می‌شود و فعلاً انجام نشده است.

## وضعیت انتشار — شفاف

- مخزن GitHub وجود دارد، اما **انتشار وب‌سایت انجام نشده است**؛ ساخت مخزن به معنای انتشار بازی نیست.
- Frontend فعلی به SDK بله و API سروری متصل شده است؛ برای استفادهٔ واقعی باید Backend و PostgreSQL روی Liara پیکربندی و مستقر شوند. اجرای فایل HTML به‌تنهایی همچنان فقط پیش‌نمایش محلی است.
- فایل بازی مستقل است و برای اجرا **به سرور نیاز ندارد** — کافی است `index.html` در مرورگر باز شود.
  (تنها وابستگی اختیاری: فونت وب Vazirmatn از CDN؛ بدون اینترنت، فونت جایگزین سیستم استفاده می‌شود.)

## صفحات نسخهٔ فعلی

- **دروازه‌ها** — صفحهٔ خانه با ۱۳ کارت دروازه (قفل/گشوده)
- **نقشهٔ جهان** — مسیر پیچان با ۱۳ گره و برچسب نام‌ها
- **پروفایل** — آواتار کپسولی، آمار، نوار پیشرفت، کد QR (نمونهٔ تستی)
- **صحنهٔ اکتشاف «دریای شیشه‌ای»** — فقط دروازهٔ ۱؛ کپسول بازیکن + ۳ شخصیت کپسولی،
  دستهٔ حرکت لمسی + کلیدهای جهت

## وضعیت واقعی قابلیت‌ها

فهرست دقیق هر قابلیت با یکی از این چهار وضعیت — در
[`docs/SPEC.md`](docs/SPEC.md) نگه‌داری می‌شود:

1. پیاده‌سازی و آزمایش‌شده
2. پیاده‌سازی‌شده ولی آزمایش‌نشده (یا آزمون محدود)
3. صرفاً نمونه یا نمایشی
4. هنوز پیاده‌سازی‌نشده

خلاصهٔ صادقانه: **تنها دروازهٔ ۱ محتوای نمونه دارد** (مأموریت، مینی‌گیم اکتشاف آزاد،
یک متن پیش‌بینی نمونه). هیچ‌یک از ۱۳ دروازه سیستم واقعیِ تکمیل مأموریت، پاداش،
افزایش پیشرفت یا باز شدن دروازهٔ بعدی را ندارند. QR فعلی **نمایشی** است و قابل اسکن نیست.

## رابطهٔ «۱۳ دروازه» با مفهوم «۷۷ سرزمین»

- **مفهوم اصلی بازی:** هفتاد و هفت سرزمین.
- **نسخهٔ فعلی:** ۱۳ دروازه به‌عنوان بخش ابتدایی/پیش‌درآمد ساختار.
- این ۱۳ دروازه معادل کل جهان بازی نیستند و نباید با مفهوم ۷۷ سرزمین اشتباه گرفته شوند.

## Backend و مینی‌اپ بله\n\n- Backend: Python 3.11+ / FastAPI / SQLAlchemy / PostgreSQL\n- میزبانی مصوب: Liara (استقرار هنوز انجام نشده)\n- معماری و تصمیم‌ها: [docs/DECISIONS.md](docs/DECISIONS.md)\n- Backend: [backend/README.md](backend/README.md)\n- وضعیت قابلیت‌ها و تست‌ها: [docs/SPEC.md](docs/SPEC.md)\n\n## ساختار مخزن

```
index.html                      ← فایل اصلی و مرجع بازی (تک‌فایل، مستقل)
docs/SPEC.md                    ← مشخصات + جدول وضعیت قابلیت‌ها
docs/GITHUB.md                  ← اتصال مخزن، امنیت توکن، وضعیت انتشار
scripts/push.sh                 ← push به GitHub (بدون توکن در دستور/URL/خروجی)
scripts/git-credential-darvazeha← helper محلی اعتبارنامه (بدون هیچ رازی)
scripts/screenshot.py           ← اسکرین‌شات صفحات برای راستی‌آزمایی
scripts/verify.py               ← آزمون خودکار ۱۳ موردی (Playwright)
download/                       ← تحویل محلی (نسخهٔ نسخه‌دار + اسکرین‌شات‌ها) — عمداً در مخزن نیست
```

پوشهٔ `download/` در `.gitignore` است و عمداً وارد مخزن نمی‌شود (محتوای غیرضروری برای مخزن).
مرجعِ کد همان `index.html` در ریشهٔ مخزن است و نسخهٔ نسخه‌دار `darvazeha-v1.html`
فقط یک کپی یخ‌زده و بایت‌به‌بایت یکسان از آن برای تحویل به کاربر است.

## ذخیره‌سازی و محدودیت آن

پیشرفت فقط در `localStorage` مرورگر ذخیره می‌شود:

- بین دستگاه‌ها/مرورگرها همگام **نمی‌شود**؛
- با پاک‌کردن داده‌های مرورگر از بین می‌رود؛
- حساب کاربری یا سرورِ ذخیره‌سازی وجود ندارد.

## فرایند توسعه (الزام)

1. پس از هر تغییر (کوچک یا بزرگ): کامیت جداگانه با پیام دقیق
2. بلافاصله پس از هر کامیت: push (اسکریپت `scripts/push.sh`)
3. هش کامیت‌ها در گزارش‌ها ذکر می‌شود
4. هیچ رازی (توکن/کلید) هرگز به مخزن، تاریخچه یا خروجی فرمان راه نمی‌یابد
