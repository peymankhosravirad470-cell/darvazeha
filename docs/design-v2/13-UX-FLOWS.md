# سند ۱۳ — UX: جریان صفحه‌ها و تجربهٔ کاربری سیستم‌های v2

> **نسخهٔ v2.0 پیش‌نویس برای تصویب | ۲۰۲۶-۱۱-۰۲ | وابسته به: Design System «راهنمای سفر» فاز UX قبلی (download/ux-v2)، سند ۰۵ (بازار)، سند ۰۸–۱۰ (هماورد/حکومت)**
> اصل [قطعی]: رابط ساده، قابل فهم، خلوت و موبایل‌محور. بازارچه شلوغ و گیج‌کننده نیست؛ خرید در چند گام روشن انجام می‌شود. تمام صفحات RTL و Mobile-First.

## ۱. قرارداد حالت‌های سراسری همهٔ صفحه‌ها [پیشنهادی — الزام‌آور برای پیاده‌سازی]

| حالت | قاعده |
|---|---|
| خالی (Empty) | تصویر سبک + یک جملهٔ توضیح + یک اقدام پیشنهادی (هرگز صفحهٔ مرده) |
| بارگذاری (Loading) | اسکلت‌نما (Skeleton) با ابعاد واقعی محتوا؛ بدون اسپینر بی‌متن بیش از ۱ ثانیه [عدد آزمایشی] |
| خطا (Error) | پیام کوتاه فارسی + «تلاش دوباره»؛ خطاهای شبکه با حفظ ورودی کاربر |
| تأیید عملیات حساس | هر عمل مالی/غیرقابل‌بازگشت: صفحهٔ تأیید جدا با نمایش تفکیکی (کالا/قیمت/کارمزد/جمع) + کلید تأیید دوم |
| پیام موفقیت | لحظه‌ای، با اقدام بعدی روشن («رفتن به آگهی»، «دیدن رسید») |
| وضعیت معامله | نشانگر سه‌حالته: در حال انجام → انجام شد / برگشت خورد؛ با شمارهٔ معامله قابل جستجو |
| موبایل | عمل اصلی ثابت پایین صفحه؛ بدون اسکرول بی‌مورد؛ لمس هدف ≥ ۴۴px [عدد آزمایشی] |

## ۳. جریان‌های کلیدی کاربر (User Flows) [پیشنهادی]

### ۳.۱ خرید در بازارچه — هدف: «چند گام روشن» [قطعی]
```
بازارچه → فیلتر/جستجو → آگهی → جزئیات → «خرید»
→ صفحهٔ تأیید (تفکیک مبلغ + کارمزد) → تأیید دوم → نتیجهٔ فوری
   ├─ موفق: رسید + کالا در انبار + «مشاهدهٔ انبار»
   ├─ کم‌موجودی: «موجودی کافی نیست» + اقدام پیشنهادی
   └─ فروش رفت (رقابت): پیام روشن + پیشنهاد آگهی مشابه
```
دوبار لمس دکمه: کلید idempotency — کاربر پیام «در حال انجام» می‌بیند نه خرید دوم (سند ۰۵ §۲).

### ۳.۲ فروش (تولید تا پول)
```
تولید (سند ۰۴) → انبار → «عرضه» → قیمت با راهنمای نرخ پایه → تأیید → آگهی فعال
→ اعلان فروش → «توکن دریافت شد» → تاریخچهٔ معامله
```

### ۳.۳ مشارکت در هماورد
```
اعلان دورهٔ ثبت‌نام → ثبت‌نام/اعلام تمایل → آماده‌سازی (وظیفه‌برداری)
→ رقابت (اعمال روزانه + رؤیت امتیاز زنده) → کارت نتیجه → پاداش/اعتراض
```

### ۳.۴ مسیر فردی (اگر کاربر هرگز سکونتگاه را نبیند)
```
دروازه‌ها/نقشه (v1 فعلی) → مودال ۴ سنگ‌راه → مأموریت‌ها → مرحله → مینی‌گیم
→ ارزیابی → پاداش → مرحلهٔ بعد …  (هیچ گام وابسته به دیگران — سند ۰۳ §۱)
```

## ۴. اتصال به طراحی مصوب UX قبلی [قطعی]

- **Design System «راهنمای سفر»** (تایپوگرافی RTL، اجزا، حرکت، لهجهٔ سرزمینی) بدون تغییر معنایی گسترش می‌یابد: رنگ‌های جدید فقط «لهجهٔ سرزمینیِ» هر سکونتگاه/دروازه.
- **مودال ۴ سنگ‌راه** مودال جزئیات دروازه می‌ماند؛ صفحات اقتصادی جدید در ناوبری اصلی (پروفایل/سکونتگاه) قرار می‌گیرند، نه درون مودال دروازه — دروازه «محتوا» است، بازار/حکومت «نظام» است.
- نگاشت به ساختار فعلی HTML (طبق جدول ۵ فاز UX): `view-gates/view-map/view-profile/gate-modal/scene/joy` حفظ؛ صفحات v2 به‌عنوان viewهای جدید (`view-settlement`, `view-market`, …) اضافه می‌شوند — **هیچ عنصر آزموده‌ای حذف نمی‌شود**.
- آمار پروفایل `st-gates/st-missions/st-stars` به دادهٔ واقعی وصل می‌شود + سه شاخص جدید پیشنهادی: `st-tokens, st-missions-collective, st-contributions` [نیازمند تصویب].

## ۵. ریسک‌ها

| ریسک | کنترل |
|---|---|
| شلوغی با ۲۱ صفحه | ناوبری سه‌لایه: خانه (بازی فردی) / سکونتگاه (جمعی) / پروفایل |
| سرریز شناختی اعداد اقتصادی | پیش‌فرض‌های خوب + توضیح‌های یک‌خطی؛ جزئیات لایهٔ دوم |
| کلاهبرداری احساسی کاربر تازه‌وارد در بازار | تأیید دوم + نمایش کارمزد + راهنمای نرخ |

## ۶. تست پذیرش (خلاصه)

1. همهٔ ۲۱ صفحه حالت خالی/بارگذاری/خطا دارند. 2. خرید ≤ ۵ گام از بازارچه تا رسید. 3. هر عمل مالی تأیید دوم و نمایش کارمزد دارد. 4. همهٔ صفحات در عرض ۳۶۰px بدون اسکرول افقی سالم‌اند. 5. کارت نتیجهٔ هماورد هر ۹ معیار را تفکیک می‌کند.

## ۷. نیازمند تصویب کارفرما

1. ناوبری سه‌لایه و جایگاه صفحات (§۴).
2. سه شاخص جدید پروفایل.
3. نمونه‌های بصری این صفحات در فاز بعدی طراحی (پس از تصویب اسناد).

**وضعیت این سند: ✅ طراحی کامل — نمونه‌سازی بصری صفحات جدید فقط پس از تصویب اسناد شروع می‌شود (الزام کارفرما).**
